# Improvements

Changes that improve the product beyond the launch-blocking fixes listed in `README.md` (Part 1). Each entry states the problem, the change and where the evidence is.

| # | Area | Problem | Change | Evidence |
|---|---|---|---|---|
| 1 | UX / errors | When the assistant failed, the customer saw internal configuration text in the chat ("I could not complete the request: Set OPENAI_API_KEY in .env.local…"), and the same text again in a red alert. | The customer now sees a short, plain reply ("Sorry, I can't answer right now. Please try again in a few minutes or ask for human support."), with no duplicate alert. The technical cause goes to the server log (`agent_run_failed <runId> <cause>`) and to `runs.error`, where operators can see it. Document search without a key shows "This feature is temporarily unavailable." The search API still returns `missing_openai_api_key` with configuration guidance, which the public invariants require. | `evidence/friendly-errors.txt`; `npm test` 34/34; files: `src/agent/run.ts`, `app/api/[...path]/route.ts`, `src/auth.ts`, `app/page.tsx` |
| 2 | Agent / language | The prompt said "Reply in the customer's language". The model read it as the customer's nationality: Carla (Spanish name, ES IBAN) got Spanish answers to English messages in 2 of 3 runs. | The instruction now says to reply in the language of the customer's latest message, not the one suggested by name, country or account data. | `evidence/agent-language-and-single-account.txt` (3/3 English after; Spanish input still gets Spanish) |
| 3 | Agent / transfers | The prompt only covered customers with more than one account, so the agent asked Hugo "which account?" although he has just one. | With exactly one account, the agent uses it as the source without asking; with several it still asks and never chooses. The proposal card still requires explicit confirmation. | same file: Hugo gets a proposal in one turn |
| 4 | Retrieval / chunking | Documents were cut every 650 characters: in 44 of 80 documents the fee and its waiver or exceptions landed in different chunks, 168 cuts fell inside a word, CSV notices kept their raw quotes and HTML line breaks were lost. | One chunk per document section; long sections split at paragraph or sentence boundaries. Each chunk starts with the title, id, version and validity, so the embedding and the model both see them. CSV and HTML are converted to clean text. 480 chunks, terms never split. Index re-embedded and exported so `setup`/`reset` load it. | `evidence/agent-context-and-robustness.txt`; `src/ingestion/chunker.ts`, `src/ingestion/pipeline.ts` |
| 5 | Agent / customer profile | The agent knew nothing about the customer before calling tools, so "my fee" had no product, and retrieval treated every product equally. | Each turn the server builds a bounded profile from authoritative sources: accounts and balances from the bank, products held and their current documents, open cases, the 5 latest transfers and the 5 latest previous conversations. Search reserves 2 of its 5 slots for the best current excerpts of the customer's own products; the other 3 go to the closest matches, so a question naming another product still finds it. (A small score boost was tried first and failed for generic questions: "my monthly fee" ranked other products' fee documents higher.) | `evidence/agent-context-and-robustness.txt` (Lucía gets Aurora, Hugo gets Horizon, Hugo asking about Aurora gets Aurora); `src/agent/context.ts`, `src/retrieval/search.ts` |
| 6 | Transfers / interrupted dispatch | If the server stopped between confirmation and the bank's answer, the transfer stayed "processing" forever and status checks never asked the bank. | After a 60-second timeout from confirmation, the fixed reference is looked up in the bank: found = completed, absent = not executed, bank unreachable = pending verification. Runs on status checks, on the dashboard and at the start of each agent turn. The idempotent reference means this never sends money twice. | `tests/transfers.test.ts` (interrupted dispatch); `src/banking/actions.ts` |
| 7 | Agent / turn completion | After 7 tool rounds the customer got a generic message and the run was still recorded as completed; a reply cut off at the output limit was saved half-written. | The last round offers no tools, so the model always ends with an answer from the tool results. A reply cut off at the output limit is retried once with more room; any other incomplete reply gets the plain fallback message and the run is recorded as failed or `no_answer` with its reason. | `src/agent/run.ts` |
| 8 | Agent / conversation lock | If saving the first message failed, the conversation stayed locked ("Wait for the previous response to finish") until the server restarted. | The lock is released in a `finally` around the whole turn, and the run and message rows are written in one transaction. | `src/agent/run.ts` |
| 9 | Support cases | Asking for a human again while a case was open dropped the new summary, so the operator never saw it. | The new information is appended to the open case with a timestamp; the tool returns `updated: true`. | `tests/transfers.test.ts` (repeated request_human); `src/agent/tools.ts` |
| 10 | UI / manual transfer | Amounts such as "1.234,56" became NaN and the customer saw "Invalid request data." | A parser accepts 12.50, 12,50, 1,234.56, 1.234,56 and 1.234 (thousands); unclear input such as 1.2.3 gets a clear message asking for the amount again. The proposal card still shows the amount before confirmation. | `tests/amount.test.ts`; `src/amount.ts`, `app/page.tsx` |
| 11 | Agent / missing documentation | When no document answered, the agent described its internals ("the excerpts surfaced…") and could open a support case on its own. | It says plainly that the published information does not cover the question, offers human support and only opens a case if the customer asks or accepts, then keeps helping. | `evidence/agent-context-and-robustness.txt` (no case opened by the questions; one opened after "Yes please") |
| 12 | Agent / scope | The assistant answered anything: asked "que tiempo hace hoy?", it replied about the weather and asked which city. The guardrails (input screen, abuse control, reply judge) lived on an unmerged branch, and the main prompt had no scope rule. | Merged the guardrails branch. Added a scope rule to the agent instructions: unrelated requests get one sentence redirecting to banking, with no answer and no follow-up questions. This covers topics the narrow input screen does not list, such as weather or sport. When the judge rejects a draft as irrelevant, the customer gets the scope redirection instead of "I could not double-check my answer". | `evidence/guardrails-merge.txt` |
| 13 | Guardrails / language | Fixed replies that skip the model (out of scope, judge block, failure, chat paused) were English only, so Spanish messages got English answers. | `src/agent/replies.ts` picks Spanish or English from the customer's message for every fixed reply. | `tests/replies.test.ts`; `evidence/guardrails-merge.txt` |
| 14 | Guardrails / judge false positive | The reply judge blocked a correct answer to "¿Cuánto es mi comisión mensual?" because it read the source citation `[horizon-fees-2026 v2]` as internal. | The judge instructions now say citations point to published documents and are required, and that a short redirection to banking is relevant. 6 of 6 live banking questions were sent after the change. | `evidence/guardrails-merge.txt` |
